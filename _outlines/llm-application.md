## 目标读者与学习目标

面向已经使用过聊天式大模型，希望将其用于学习、资料整理、科研辅助和软件开发的学生与开发者。基础篇只要求能够创建文件、阅读普通文本并进行多轮对话；Skill 与工具篇逐步引入 Markdown、目录结构和必要的终端操作。简单脚本、JSON 和 API 概念在首次需要时补充。

系列的核心问题是：如何把一个实际需求表达清楚，提供合适的资料与约束，组织可检查的执行过程，并将有效方法复用于后续任务。

完成系列后，读者应能够：

1. 根据任务选择聊天、文件处理、检索或具备工具能力的 Agent，并说明结果的验证方式。
2. 编写包含目标、材料、约束、输出要求与验收标准的 Prompt，使用具体反馈完成多轮修订。
3. 组织项目资料与任务状态，为长任务建立检查点，并向新对话交接已完成工作。
4. 核对资料来源、时效与证据，将缺失、冲突和推断保留在结果中。
5. 使用和评估已有 Agent Skill，检查适用范围、依赖与实际执行效果。
6. 连接适用工具，检查参数、权限、实际执行结果及失败原因。
7. 建立可恢复的工作流，用固定任务样例比较正确性、完整性、耗时和成本。

## 内容范围与技术路线

主线为“任务表达—多轮协作—上下文组织—资料处理—Skill 复用—工具连接—自动化与验证”。前半部分讲通用使用方法，后半部分以支持 Agent Skills 和工具调用的宿主开展实践。

Skill 实操优先采用 Codex；文件上传、联网搜索、项目规则、MCP 和自动化功能须在写作时核对所选产品的实际支持情况。每篇明确宿主、执行环境、必要权限和验证日期，不将一个产品的路径、调用方式、记忆机制或授权行为推广为所有大模型产品的共同规则。

API 是结构化输出和自动化的可选扩展路径。正文优先给出普通用户可完成的最小案例；需要 API 的分支单独说明账户、计费、密钥和脚本依赖，不把这些条件设为前半部分的阅读前提。

模型选择以任务质量、模态、上下文、工具支持、延迟与预算为依据。具体模型名称、价格、额度和功能入口放在对应文章的环境说明中，并注明核对日期。评估方法在第九篇完整展开。

模型训练、微调、推理服务部署、向量数据库工程、完整 MCP 服务开发和复杂多 Agent 框架可作为后续独立方向。本系列只解释理解案例所需的原理与最小流程。

## 核心概念与职责

| 概念 | 本系列的含义 | 主要讲解位置 |
| --- | --- | --- |
| Prompt | 对本次任务的指令表达，包括目标、限制、输出要求及必要示例 | 第一篇 |
| 上下文 | 模型在当前任务中可使用的指令、输入资料、历史消息、工具结果和任务状态 | 第三篇 |
| 项目规则 | 在特定项目或目录范围内持续适用的约定；加载范围和优先关系依宿主而定 | 第三篇 |
| Agent Skill | 以 `SKILL.md` 和可选参考资料、模板、脚本等组织的可复用任务流程 | 第六篇 |
| 工具 | 由宿主或应用提供的数据读取、计算、文件操作等执行能力 | 第七篇 |
| MCP | 连接宿主与外部工具、资源等能力的协议；本系列以工具连接为主要案例 | 第七篇 |
| 插件 | 由具体平台定义的扩展包装形式，可能包含 Skill、工具连接及其他资源 | 第六、七篇 |
| 工作流与 Agent | 工作流组织预先定义的执行步骤；Agent 可根据任务状态选择行动。两者可组合使用 | 第八篇 |
| 评估 | 依据预先定义的任务样例与标准检查输出和执行过程，并比较不同版本 | 第九篇 |

Skill 的文件结构与按需加载参考 [Build skills](https://learn.chatgpt.com/docs/build-skills)。Skill 可以只包含指令与资源，也可以组织工具操作；实际操作依赖宿主提供的能力和授权。Skill 与 MCP 的分工参考 [Skills – Plugins](https://developers.openai.com/plugins/concepts/skills)。

Prompt、项目规则、Skill 和上下文管理会改变模型在任务中的输入与执行约定，其效果须用实际任务检验。上下文窗口、产品记忆和跨对话交接分别说明，避免把材料上传、保存偏好或载入 Skill 描述为对基础模型的重新训练。

## 贯穿案例与资料契约

### 练习项目

项目暂定为 `llm-practice-lab`：整理几份技术工具说明、一个项目需求和小型实验记录，形成有来源的工具比较表与学习摘要。主题采用“Windows 与 Linux 实验日志整理”，可与已有命令行系列关联，但每篇给出独立输入，不要求先完成其他系列。

初始材料使用自编的虚构工具说明，明确标注“教学模拟资料”，提供可人工核对的答案。设置版本差异、缺失字段和相互冲突的条目，便于检验模型的处理方式。第四篇再加入实际官方文档与固定快照；真实资料和模拟资料使用独立来源编号，不能把模拟条目写成真实产品能力。

项目随文章演进：单篇摘要 → 多轮比较报告 → 项目约束与交接 → 证据表 → 结构化记录 → 可复用 Skill → 工具读取 → 可恢复工作流 → 版本对照评估。

下面的目录为后续完整配套项目规划；当前已建立导读、第一至九篇所需的 README、固定输入、提示词、边界变体、阶段记录、交接项目、官方资料局部摘录、字段契约、文件导出与检查程序及独立参考答案，其余目录按专题进度创建：

### 输入与记录约定

来源索引至少保留 `source_id`、标题、资料类型、URL 或本地文件位置、版本、发布日期和采集日期。未知信息留空并解释原因；实际网页地址在正式准备案例时确定，示例占位符必须先说明替换方式。

第四篇形成的证据表与第五篇输出的 JSON/TSV 采用相同语义。第六篇 Skill 使用、第七篇工具读取和第八篇工作流复用这一契约，不在各篇改变字段名称或缺失值规则。

| 字段 | 含义与约束 |
| --- | --- |
| `record_id` | 一条记录的唯一标识；由输入或明确规则确定，不依赖当前文件行号 |
| `source_id` | 来源索引中的标识；不能生成不存在的来源 |
| `locator` | 页码、章节、行号或可定位片段；缺失证据时可为空，不能编造定位 |
| `subject`、`property` | 被比较对象及属性；统一名称映射在提取前给出 |
| `value`、`unit` | 原资料支持的值与单位；未知值在 JSON 中为 `null`，TSV 中为空单元格 |
| `status` | `supported`、`missing`、`conflict` 或 `not_applicable`；具体判定规则在第四篇建立 |
| `note` | 版本差异、冲突、转换或缺失原因；推断明确标注且不能替代原始事实 |

`supported` 表示本次输入资料能够直接支持该条记录，不表示资料中的陈述已被证明永远正确。冲突记录保留各自来源和值，并通过 `subject` 与 `property` 关联。来源索引保留版本和日期，便于判断同一属性的差异是否来自时间范围。

初始输入明确列出待提取的记录集合，验收检查唯一标识、集合完整性、字段映射和证据位置；模型不得自行补造事实来填满表格。列名正确、JSON 可解析和表格美观分别只是部分检查，还须核对内容。

### 案例素材与验收依据

准备小而完整的资料包，至少包含正常输入、缺失值、来源冲突、重复记录、无关材料和工具失败样例。外部指令干扰采用无害模拟文本，只用于检查模型是否将资料内容误作任务指令。

`expected/` 保存经人工核对的参考记录及规则检查结果；文件、来源和字段检查尽量采用确定性脚本。开放式摘要用覆盖范围、证据一致性和读者适配等评分标准人工检查。模型评审可作辅助，其结论须与参考资料或人工判断核对。

## 导读：大模型应用基础与学习路径

**读者与前提**：使用过基本对话功能，无需编程、API 或 Agent 经验。

**核心问题**：根据任务特点选择使用方式，并建立对资料、能力、限制和验证的基本认识。

**内容边界**：提供概念模型、学习路线和最小任务；Prompt 模板、项目规则、Skill 安装及工具配置分别交给后续专题。

**主要案例**：对同一份小型说明资料开展摘要、事实提取和工具操作需求分析，分别列出输入、预期输出与检查方式。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 任务类型与能力边界 | 生成、转换、检索、计算和操作；比较摘要、版本查询与文件整理 | 能说明任务需要资料、外部信息还是执行能力 |
| 2. 输入、上下文与输出 | token、上下文窗口、知识时效与输出不确定性；检查资料摘要中的无依据内容 | 能区分模型已有知识、当前输入与实际工具结果 |
| 3. Prompt、Skill 与工具 | 用资料整理项目展示指令、可复用流程与工具的关系 | 能解释不同组件负责什么以及如何组合 |
| 4. 模型选择与验证 | 质量、延迟、模态、工具支持与预算；制定最小验收表 | 能按需求选择路线并安排必要检查 |
| 5. 学习顺序与实践入口 | 介绍练习资料、专题依赖和独立阅读入口 | 能从自己的任务选择后续章节 |

**练习与验收**：为三个任务填写“目标—输入—能力—输出—验证”表，至少识别一个需要实时核对的信息和一个需要实际执行的操作。

## 第一篇：提示词结构与示例引导

**读者与前提**：能够提交任务并阅读输出；使用导读提供的小型资料。

**核心问题**：把模糊请求改成范围明确、输出可检查的任务描述。

**内容边界**：聚焦单次任务表达和少量示例；复杂阶段协作在第二篇，资料目录与长期规则在第三篇，结构化输出接口在第五篇。

**主要案例**：将一份工具说明整理成面向初学者的学习摘要，对照原始请求、明确约束版和必要示例版的输出。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 任务目标与输出对象 | 用途、读者、交付物和范围；将“总结资料”拆成可检查要求 | 能说明摘要解决什么问题、应覆盖哪些内容 |
| 2. 材料与指令组织 | 背景、约束、分隔符与冲突指令；明确引用材料的边界 | 能减少资料内容与任务要求的混淆 |

| 5. 对照改写与误区 | 角色设定、重复限制、冗长模板和模型差异；一次改变一个主要因素 | 能根据错误改写 Prompt，并保留对照结果 |

**练习与验收**：提交任务模板和对照输出，逐项核对指定信息、资料一致性及格式。缺失资料须保留为未知，不能为满足篇幅补造事实。示例的作用参考 [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)。

## 第二篇：多轮协作与任务分解

**读者与前提**：掌握第一篇的任务描述与验收方法；无需自动化工具。

**核心问题**：通过澄清、计划、阶段产物和具体反馈完成较复杂任务。

**内容边界**：讲人在对话中管理任务；程序状态机、自动重试和 Agent 编排在第八篇，跨对话资料交接在第三篇。

**主要案例**：围绕三份说明资料完成工具比较报告，依次确认需求、提取信息、形成比较、修订结论。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 需求缺口与澄清范围 | 必要问题、合理假设和可独立推进的工作；分析模糊需求 | 能区分影响结论的缺口与可自行决定的细节 |
| 2. 子任务与依赖关系 | 先提取再比较、先确定标准再形成结论；画出简短依赖图 | 能按依赖组织阶段，避免先写结论再补材料 |
| 3. 阶段产物与检查点 | 计划、记录表、报告草稿及验收状态 | 能检查中间结果后再推进后续任务 |
| 4. 反馈定位与局部修订 | 用记录标识、具体段落、证据和期望值定位问题 | 能修正局部错误，并复查受影响的后续结论 |
| 5. 推理任务与可检查依据 | 要求必要假设、计算步骤、引用和简明说明；区分自我检查与外部验证 | 能要求有用的解释，并用独立依据检查结果 |

**练习与验收**：保存阶段计划、一次具体错误反馈和修订后的产物，确认指定错误已修复、已正确的信息仍保留。对“逐步思考”等提示技巧按模型与任务验证效果；推理模型的相关边界参考 [Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)。

## 第三篇：上下文组织与项目约束

**读者与前提**：能够管理文本文件，理解当前任务和阶段产物。

**核心问题**：在长任务和多次对话中保留相关材料、约束与进度。

**内容边界**：聚焦人工可维护的资料组织与项目规则；自动检索在第四篇，已有 Skill 使用在第六篇，自动状态持久化在第八篇。

**主要案例**：为资料整理项目建立说明、来源索引、项目规则和状态摘要，在新对话中恢复任务。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 资料相关性与输入预算 | 全量粘贴、选择片段和索引入口；比较冗余与必要资料 | 能提供完成当前步骤所需的内容 |
| 2. 项目文件与稳定约定 | 目标、输入输出、目录说明和字段定义；建立项目入口文件 | 能找到规则、原资料和当前产物 |
| 3. 项目规则与作用范围 | 以 `AGENTS.md` 说明目录约定、任务要求和宿主加载机制 | 能核对实际生效范围，处理重复或矛盾规则 |
| 4. 状态摘要与任务交接 | 已完成、待完成、假设、失败、来源位置及下一步 | 能形成新对话可执行的交接说明 |
| 5. 上下文漂移与恢复 | 过期材料、遗漏要求和错误摘要；使用原始文件核对 | 能从持久产物恢复状态并纠正摘要偏差 |

**练习与验收**：新建对话并仅提供项目入口与交接材料，检查其能否正确复述范围、定位证据、识别未完成项并完成下一步。记忆、项目规则和自动压缩的产品行为须在正文中分别核对。

## 第四篇：资料检索与事实核验

**读者与前提**：能够阅读资料并使用来源索引；具备联网检索能力时开展实时分支。

**核心问题**：从检索结果形成可追溯结论，并识别过时、缺失、冲突和无依据推断。

**内容边界**：讲使用层面的搜索、文档定位和 RAG 基本模型；向量索引、嵌入服务和数据库部署留作后续方向。记录文件的具体格式在第五篇展开。

**主要案例**：为工具比较表逐项补充依据，加入版本差异、缺失信息和相互冲突的来源，再用实际官方资料演示检索与快照保存。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 检索问题与资料范围 | 关键词、限定条件、官方资料和检索时间 | 能将比较属性转成具体检索问题 |
| 2. 搜索结果与原文读取 | 摘要、原页面、文档章节与文件检索；演示定位链路 | 能检查真正支持结论的原文，保留定位信息 |
| 3. 证据与来源记录 | 来源编号、版本、日期和支持片段；建立统一证据表 | 能让读者重新找到依据 |
| 4. 缺失、冲突与推断 | 缺失值、不同版本的陈述、结论范围和推断标签 | 能保留不确定性，并说明结论成立的条件 |
| 5. 检索增强与干扰处理 | 查询—取回材料—基于材料回答；模拟无关资料和外部指令干扰 | 能将检索内容作为资料核对，识别偏离任务的指令 |

**练习与验收**：每条关键比较结论至少关联一条实际支持它的记录；输入中设置的缺失与冲突均被保留。引用存在、引用支持当前结论和引用覆盖全部关键结论分别检查。

## 第五篇：文件处理与输出规范

**读者与前提**：掌握来源与证据记录；正文补充 JSON、TSV 和必要的字段概念。

**核心问题**：把不同输入中的信息准确映射到稳定、可检查的交付物。

**内容边界**：重点讲输入准备、字段与格式契约、确定性检查；大型文档排版、复杂表格公式、PPT 设计和完整 OCR 系统作为应用专题。API 结构化输出以最小扩展介绍。

**主要案例**：将工具说明、简短 PDF 或配套文本摘录、实验记录整理成一份 Markdown 报告和语义一致的 JSON/TSV 文件。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 文件输入与解析限制 | 文本层、扫描页面、图片、表格与原生文件解析；选择必要输入 | 能说明实际读取了哪种内容及可能遗漏什么 |
| 2. 模板与字段映射 | 固定键、名称映射、单位、记录标识、缺失值和冲突 | 能先确定契约再提取，保持源信息与模板要求 |

| 5. 错误修复与最终交付 | 只修正错误记录，重新检查关联报告；文件产物与聊天描述 | 能交付可读取文件，并定位尚未解决的问题 |

**练习与验收**：JSON 与 TSV 的记录集合、值和状态一致，必需字段通过检查；缺失值符合契约，来源和定位真实。API Structured Outputs 的支持范围、拒绝和未完成输出须就近说明；结构合规仍需事实核验，参考 [Structured model outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。

| 2. 来源、依赖与操作范围 | 来源和版本、脚本副作用、网络目标、凭据需求及权限 | 能在安装前检查将执行什么、访问什么 |

## 第七篇：工具调用与 MCP

**读者与前提**：理解工具与 Skill 的分工；拥有可配置工具的宿主和有权读取的练习资料。

**核心问题**：连接适用工具，理解参数和返回值，并判断任务是否实际执行成功。

**内容边界**：讲工具使用、MCP 连接及基础故障定位；不展开完整服务器实现、远端部署或复杂 OAuth 开发。认证概念服务于实际连接步骤。

**主要案例**：连接一个限定在练习资料范围内的只读工具，完成查询来源、读取片段和整理记录；再使用可控失败样例排查问题。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 工具定义与执行结果 | 工具名称、说明、参数、返回结构及执行状态 | 能区分发出调用、收到结果与达成任务 |
| 2. MCP 连接与能力发现 | 宿主、客户端、服务端及工具列表；核对实际支持方式 | 能说明连接各方的职责 |

| 5. 失败分类与恢复 | 无连接、无权限、无记录、参数错误和执行失败 | 能定位故障层次，避免将失败当成空结果 |

**练习与验收**：用一次成功读取和至少两种不同失败验证行为；输出引用真实返回内容，失败保留原因。权限、外部数据与敏感操作的边界参考 [MCP servers](https://developers.openai.com/api/docs/guides/tools-connectors-mcp)，具体宿主配置在写作时另行核对。

## 第八篇：Agent 工作流与自动化

**读者与前提**：能够检查阶段产物和工具结果；具备基础脚本阅读能力时开展程序化分支。

**核心问题**：组织多阶段执行，正确处理依赖、失败、恢复和停止。

**内容边界**：以单 Agent 或简单固定流程完成最小案例；多 Agent 只介绍适用条件、任务划分和额外成本。计划、并发、调度和重试机制依执行宿主核对。

**主要案例**：自动执行“检索或读取—提取—核验—生成”，每阶段保存产物；注入一次读取失败，恢复后继续完成报告。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 工作流与动态决策 | 固定步骤、条件分支与 Agent 选择；比较同一任务的组织方式 | 能选择满足需求的最小执行结构 |
| 2. 输入输出与阶段依赖 | 复用资料契约；上游结果不合格时限制下游执行 | 能检查阶段前提并阻止错误传播 |
| 3. 状态、运行标识与记录 | `run_id`、阶段状态、中间产物和错误日志 | 能知道已经完成什么、还缺什么 |
| 4. 重试与失败恢复 | 临时错误、永久错误、有限重试、检查点和重复执行 | 能从失败位置恢复，保护既有产物 |
| 5. 停止条件与人工检查 | 任务完成、证据不足、权限缺失、预算达到上限和写入操作 | 能说明流程为何停止及下一步需要什么 |

**练习与验收**：失败运行和恢复运行均有记录；上游核验失败时不发布无依据结论；恢复后无重复记录，已经完成的文件不被意外覆盖。流程完成报告与实际文件状态一致。

定时执行作为可选小节，说明运行环境、唤醒条件、通知条件和取消方式；任务长期运行、定期执行与多 Agent 协作分别讲解，避免合并为一种自动化机制。

## 第九篇：结果评估与成本控制

**读者与前提**：具有可重复使用的输入、明确输出契约和至少两个待比较版本；不要求购买专门评估服务。

**核心问题**：用任务质量和执行消耗判断 Prompt、Skill 或工作流的改动是否有效。

**内容边界**：聚焦项目级对照评估；模型行业排名、完整基准测试和训练优化作为独立方向。评估服务只是可选实现，不作为本篇的概念前提。

**主要案例**：先比较两个 Prompt 版本，再选择一个 Skill 改动或工作流改动，在同一固定任务集上记录输出、错误、耗时与可获得的用量。

| 章节 | 概念与案例 | 掌握结果 |
| --- | --- | --- |
| 1. 质量标准与评估对象 | 指令遵循、事实正确性、完整性、证据和工具操作；定义硬性条件 | 能将“效果更好”转成具体判据 |
| 2. 测试样例与参考依据 | 正常、边界、缺失、冲突及失败样例；开发样例与保留评估样例 | 能构造覆盖实际问题的测试集 |
| 3. 评分方法与判断限制 | 确定性检查、人工量表、盲化比较和模型评审 | 能选择适用方法并核对评审偏差 |
| 4. 版本对照与错误分析 | 固定输入、记录模型和设置、多次运行、一次主要改动 | 能区分偶然改善、稳定收益与回归问题 |
| 5. 时间、用量与预算 | 端到端耗时、调用和重试次数、可获得的 token 用量与真实费用 | 能在质量合格的前提下比较消耗与限制 |

**练习与验收**：形成版本对照报告，列出每类任务的结果、失败实例和选择理由。缺少用量或费用数据时标注未提供，不能由回答字数或订阅额度推算实际 API 成本。评估设计参考 [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，过程排查可参考 [Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals)。

## 正文写作与案例验证

### 单篇组织

延续 [AGENTS.md](../AGENTS.md) 的写作约定，通常采用“场景引入—必要概念—完整操作案例—常见问题—方法或命令速查—实践练习—参考资料”。标题与各级小标题使用简短、准确的名词性短语。

每篇开头说明读者、前置知识、输入文件、宿主与能力要求。案例中的关键步骤交代初始状态、操作目的、预期结果与验证方法。连续步骤、替代方案和独立实验分别标注；完整 Prompt、Skill 文件、脚本和所需素材在正式正文或配套目录中提供。

每篇围绕一个主要任务讲透，篇幅以完成理解和独立实践为准。低频技术采用“适用场景—最小流程—关键限制”；必要旁支链接既有文章或官方文档，避免多套互不关联的项目增加阅读负担。

### 效果比较与证据

Prompt 技巧从简单基线开始，只有出现具体问题时再增加示例、限制或阶段。角色设定、长模板、模型自检和多 Agent 的收益均须结合任务验证，不预设这些做法必然更好。请求可检查的依据、计算与来源；模型生成的解释和评分不能替代独立核验。

核心案例在独立练习目录运行，不把教程中的文件操作或外部工具写入用于博客源码。原始资料和模板保留，输出使用独立运行目录。已获授权的读取、写入、网络和安装范围须说明；涉及外部发送、正式发布或破坏性操作时，在对应步骤说明必要的人为确认。

正式验证记录至少包括宿主、模型、实际可见设置、验证日期、输入标识、Prompt/Skill/脚本版本、执行状态、产物位置和检查结论。网页版、桌面端、CLI、API、模拟工具和真实 MCP 的完成范围分别标注。

成功、失败和不完整结果均保留必要证据。一次运行通过只说明本次结果，不作为普遍可靠性的证明。对于文件产物，同时检查实际文件；对于联网结论，核对原始页面；对于工具操作，核对真实状态变化。

### 配图与练习

关系图用于解释 Prompt、上下文、Skill、工具和 Agent 的职责；依赖图用于说明阶段顺序与恢复位置；表格用于比较输出字段、权限范围、错误类型和评估结果。界面截图仅展示实际宿主操作，并注明环境与日期。

每篇练习提供可观察的完成标准。基础练习检查输入输出与证据；进阶练习加入缺失、冲突或失败样例。练习答案或参考记录与模型输入分开保存，避免评估时泄露答案。

## 发布与维护安排

1. 先完成导读及第一至三篇，为读者提供独立可用的任务模板、阶段协作和交接方法。
2. 第四、五篇先确定来源、记录与输出契约，再完成第六篇的 Skill 使用与评估。
3. 第七篇完成真实工具连接与失败样例后，第八篇再组织自动执行和恢复。
4. 第九篇复用前文案例形成固定评估集；各篇先完成自身验收，无需等待第九篇才开始验证。

系列 id 已注册为 `llm-practice`，导读使用 `series_order: 0`，后续专题按 1—9 排序。发布元数据依 [README 的系列维护说明](../README.md#系列维护) 设置；本大纲保留规划职责，不作为系列页的文章记录。系列页展示已完成的导读、第一至九篇；第九篇完成系列收尾。正文与导读中的实际文章链接同步维护。

配套示例放在 `assets/examples/llm-practice/`，运行输出放在被忽略的构建产物或独立练习目录。当前导读的完整任务要求保存在正文中，参考答案与输入文件分开。文章正文、配套 Prompt、Skill、字段定义和验证说明须同步维护。正式写作时核对相邻篇与导读链接，每个知识点保留明确的主要讲解位置。
