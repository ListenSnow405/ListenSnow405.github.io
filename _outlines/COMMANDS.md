## 目标读者与内容边界

面向需要在 Windows 本地终端和 Linux 远程服务器之间开展开发与科研计算的读者。基础篇不要求 Shell 经验；开发篇要求能够阅读基本 C++，后续专题补充必要的脚本、系统和实验概念。

科研场景以 C++/CUDA 程序、远程长任务、日志整理和性能比较为主，Python 用于环境核对及必要的数据整理。案例是教学练习，不代表作者的具体研究课题。学习目标是能够确认执行环境、运行正确的程序、识别失败、整理结果，并保存可追溯的实验记录。

六篇正文分别承担基础操作、脚本执行、构建调试、远程任务、结果整理和性能实验。Git 原理与历史恢复、CUDA 算法和内存优化、完整的调试器手册、集群管理及容器部署不在本系列重复展开；需要时引用已有专题或官方文档。

## 跨平台讲解方式

### 环境与执行位置

区分终端窗口、Shell、工具程序和操作系统。Windows Terminal 可以承载不同 Shell；Git Bash 和 WSL 不等同于 PowerShell，也不等同于远端服务器。每个案例在命令之前注明执行位置、Shell、工作目录和额外依赖。

正文以 Windows 本地 PowerShell 7 和 Linux Bash 为两条主要操作路线。涉及 PowerShell 5.1 的语法、编码或错误行为时就近说明；cmd、Git Bash、WSL 用于解释环境边界，不为每条命令提供多套版本，不要求读者安装所有环境。

| 标记 | 使用场景 | 命令块要求 |
| --- | --- | --- |
| Windows 本地 · PowerShell | 本地文件、构建、脚本、日志和 SSH 客户端操作 | 使用 `powershell`，首次说明适用版本 |
| Linux 本地或远端 · Bash | Linux 文件、构建、脚本与系统工具 | 使用 `bash`，远端操作明确主机与目录 |
| 工具内部 | GDB、CMake 配置文件等 | 使用相应语言或 `text`，不与 Shell 命令混排 |

### 对照与复用原则

共同目标先解释，再给两端操作，最后说明差异和验证方式。路径、引号、环境变量、退出状态、文本处理等高频任务提供双平台案例；Git、CMake、Python 等共用工具复用共同步骤，只区分实际不同的参数、配置和路径。

Linux 专属系统工具不制造形式上的 PowerShell 等价物。远程篇区分本地 SSH 客户端与远端 Bash 会话；资源篇区分本机状态、远端状态和调度系统分配的资源。对照表使用原生命令全名，解释别名不意味着参数兼容。

## 贯穿案例与交付物

练习项目暂定为 `terminal-lab`，前两篇只处理文本与目录，第三篇提供完整 C++ 程序，第四篇部署服务器，第五篇整理实验记录，第六篇执行对照测量。C++ 主程序采用带参考结果校验的向量计算；GPU 分支复用已有向量加法案例，正文给出明确入口，不要求基础篇具备 GPU。

```text
terminal-lab/
├── README.md             # 环境、运行入口、输入与验收说明
├── CMakeLists.txt        # 第三篇提供完整配置
├── include/              # 若案例使用头文件，必须给出完整内容
├── src/                  # 完整源码与参考计算
├── data/                 # 小型输入与输入标识
├── fixtures/             # 第五篇可独立使用的样例日志
├── scripts/              # Bash 与 PowerShell 运行脚本
├── build-linux/          # Linux 构建产物，不提交
├── build-windows/        # Windows 构建产物，不提交
├── logs/                 # 原始运行日志
├── results/              # 结构化记录与汇总表
└── metadata/             # 环境、参数、代码状态和输入校验信息
```

目录随篇目逐步引入，每篇写明起始文件、创建顺序和预期目录结构。独立实验、替代命令与连续步骤分别标注；所有占位符先说明替换方式，不把带占位符的模板称为复制即用。

### 结果记录约定

每次运行使用唯一 `run_id`，日志与结果通过该字段关联；命名包含足以避免覆盖的时间或序号。同一实验配置使用 `case_id` 关联多个版本与重复轮次，不以文件行号建立关系。

| 字段组 | 必须记录的内容 |
| --- | --- |
| 输入与配置 | 输入标识、规模、必要的校验和；算法或版本分组、完整参数、随机种子（若使用）、线程数、重复轮次 |
| 运行状态 | `run_id`、`case_id`、开始时间及时间区、退出码、状态、正确性判据与检查结果 |
| 时间与指标 | 指标名称、数值、单位、计时范围、预热状态；失败和缺失值保留原因，不填成零 |
| 环境与代码 | 主机、系统、Shell、工具链和依赖版本；提交号、工作区修改状态；有修改时保存差异及必要的未跟踪源码 |
| 设备与资源 | CPU 型号与线程设置；GPU 型号及 UUID（若使用）、驱动、资源分配和可见设备信息 |

第五篇以具有明确字段约定的 TSV 和 JSON 示例讲解。文本日志只提取已定义的格式；缺失、重复和非法字段单独标记，不默默丢弃。一般 CSV 的引号、分隔符和换行不能用简单的字段切分假定处理。

## 第一篇：终端环境与文件操作

**读者与前提**：初次接触终端的 Windows/Linux 用户；能创建普通文件，无需编程和服务器环境。

**核心问题**：确认当前环境与位置，正确管理实验文件，并处理路径、权限、编码和换行问题。

**内容边界**：只建立必要的输入输出直觉；管道机制、环境变量和脚本控制流在第二篇深入讲解。系统资源和进程管理移到第四篇。

**主要案例**：创建 `terminal-lab` 的 `data/`、`logs/` 和备份目录，写入小型文本数据，查看、搜索、复制与核对；删除练习只针对独立练习目录。

| 章节 | 概念与操作案例 | 掌握结果 |
| --- | --- | --- |
| 1. 终端与执行环境 | 终端、Shell、命令、提示符；识别 PowerShell、Bash、Git Bash、WSL 与远端会话；查看帮助 | 能说明命令由谁解释、在哪台机器执行，提示符不作为输入 |
| 2. 路径与目录 | 工作目录、绝对与相对路径、盘符、主目录、空格路径；同一目录树的两端操作 | 能定位输入与输出，不混用 Windows、WSL 和远端路径 |
| 3. 文件操作与影响范围 | 创建、复制、移动、覆盖、递归删除；列出目标、核对副本、预览批量操作 | 能区分修改原文件与生成副本，理解删除和覆盖的恢复限制 |
| 4. 文本查看与检索 | 短文件、长文件、日志头尾；按名称找文件与按内容找文本；`rg` 作为需安装的共用工具 | 能找到指定文件和匹配行，说明搜索范围及忽略规则 |

| 6. 编码与换行 | UTF-8、BOM、LF/CRLF、文件编码与终端输出编码；小型乱码与脚本换行案例 | 能区分编码与换行问题，保留源文件后完成有针对性的修复 |

**常见问题**：路径不存在、含空格路径失败、PowerShell 别名不接受 Bash 参数、中文乱码、CRLF 脚本、权限不足、误覆盖。

**命令速查**：按定位、文件操作、查看、检索、校验和帮助分类；双平台对照不承诺逐项语义完全一致。

**实践练习**：两端生成约定目录和相同文本内容，复制后用明确的字节校验或校验和核对；检索结果包含指定文件与行号。编码练习区分字节相同与文本等价；清理前能列出准确目标。

## 第二篇：Shell 执行与脚本基础

**读者与前提**：掌握第一篇路径与文件操作；能够在对应 Shell 中运行命令。

**核心问题**：让命令可靠地接收参数、组合执行、保存输出，并在失败时留下可判断的状态。

**内容边界**：解释运行脚本，不展开完整 Shell 编程语言；只负责日志生成与保存，日志提取和统计交给第五篇。长任务保活交给第四篇。

**主要案例**：先用一个小型确定性演示程序产生正常输出、错误输出和非零退出码，再构建 `run.sh` 与 `run.ps1`。预先给出完整演示程序及其依赖，第三篇再替换为编译后的实验程序。

| 章节 | 概念与操作案例 | 掌握结果 |
| --- | --- | --- |
| 1. 参数、引号与展开 | 字符串、空格、变量、通配符和命令替换；Bash 与 PowerShell 传参对照 | 输入路径包含空格时仍作为一个参数传入，能预览批量匹配范围 |
| 2. 变量与环境 | Shell 变量、环境变量、子进程、`PATH`、命令定位；临时参数及环境设置 | 能说明作用范围；临时修改已有环境变量后恢复原值，而非一律删除 |
| 3. 管道与输入输出 | Bash 文本管道与 PowerShell 对象管道；标准输出与错误流；文件输入、覆盖、追加和屏幕/文件双份输出 | 能保存需要的输出，理解显示格式与实际数据的区别 |
| 4. 退出状态与条件执行 | 外部程序退出码、Shell 成功状态、管道结果；Bash `PIPESTATUS` 与 `pipefail`；PowerShell `$LASTEXITCODE` 与 `$?`；版本差异 | 正常与失败运行都有明确判据；日志工具成功不会掩盖实验程序失败 |
| 5. 脚本组织与重复运行 | 脚本入口、参数校验、工作目录、有限循环、日志唯一命名；连续步骤与独立试验 | 能在任意启动目录下使用明确路径运行，避免重复运行覆盖结果 |
| 6. 检查与诊断 | Bash 语法检查、展开跟踪、ShellCheck；PowerShell 参数检查与错误处理最小流程 | 能定位空变量、错误参数或脚本提前结束，不把“没输出”视为成功 |

**关键限制**：`set -e` 存在条件与上下文例外，不能概括为所有错误都会退出；PowerShell 的 cmdlet 错误与外部程序非零退出码分别处理。跟踪输出可能包含参数和敏感值，示例不记录凭据。

**常见问题**：变量只对一条命令生效、重定向顺序错误、管道隐藏失败、变量被系统保留变量覆盖、脚本工作目录错误、PowerShell 5.1 不支持新语法。

**命令速查**：引号、环境设置、命令定位、重定向、退出状态、语法检查；每项标明 Shell 与适用版本。

**实践练习**：正常、错误参数、非零退出三类输入均有独立日志；含空格参数正确传入；失败状态保留为非零；临时环境变量恢复原状态；重复运行不覆盖既有日志。

## 第三篇：命令行构建与程序调试

**读者与前提**：具备基本 C++ 阅读能力与前两篇终端基础；首次需要时补充头文件、编译和链接概念。

**核心问题**：确认工具链，构建并运行正确版本的程序，用测试与调试定位错误。

**内容边界**：以完整 CMake 项目为主线。Make 只用最小依赖案例解释增量构建；Python 只讲解释器、虚拟环境和依赖定位。Git 仅用于状态与版本记录，复杂撤销链接 Git 系列。性能调优交给第六篇。

**主要案例**：提供向量计算的完整源码、参考计算和 CMake 配置，先构建正确版本，再分别引入独立的编译错误、错误结果及内存错误；各故障实验从可恢复的独立副本开始。

| 章节 | 概念与操作案例 | 掌握结果 |
| --- | --- | --- |
| 1. 编译、链接与构建 | 源码、头文件、目标文件、可执行程序与依赖；直接编译和自动构建的关系 | 能区分编译、链接及构建工具的职责 |
| 2. 工具链与依赖核对 | Windows MSVC 开发环境、Linux GCC/Clang、CMake 和调试器；Python 解释器、venv、`python -m pip` | 能核对实际执行路径和版本，确认依赖属于当前解释器或工具链 |
| 3. 完整项目与参考结果 | 创建全部文件，说明输入、算法、输出、误差规则与失败退出码 | 按正文步骤能完成项目，所有引用的头文件、源码与输入都有来源 |
| 4. CMake 配置与增量构建 | 源外构建、生成器、Debug/Release、编译器条件选项、详细构建输出；单配置与多配置区别 | 两端构建成功，实际使用期望配置；构建与 CTest 的配置一致 |

**关键限制**：CMake `-D` 用于创建或更新缓存项，排查变量名、构建目录及项目覆盖；源码时间戳和 `strings` 只能作为线索。配置阶段写入的提交号需要考虑重新配置与未提交修改，不声称提交号能完整表示二进制来源。

**常见问题**：工具找不到、MSVC 环境未初始化、编译器选项不适用、运行旧二进制、构建配置错位、链接符号缺失、运行库缺失、错误结果未被测试发现。

**命令速查**：工具核对、配置、构建、测试、运行与最小调试；Python 环境单列简短表格。

**实践练习**：Windows/Linux 均完成构建与参考结果验证；只修改一个源文件后完成增量构建；CTest 能识别故意引入的错误；记录编译器、配置、程序路径及代码状态。不能验证的平台如实标记。

## 第四篇：远程开发与任务管理

**读者与前提**：掌握第二篇的运行与日志保存方式；具备有权使用的 Linux 服务器账户。没有服务器时可阅读流程，远端实验标记为未执行。

**核心问题**：在本地与远端之间同步项目，管理长任务，识别进程状态和资源问题。

**内容边界**：任务管理与状态检查为主，不在本篇进行性能结论判定。调度系统只按实际环境给出最小入口，不默认服务器使用 Slurm，不绕过资源分配约定。

**主要案例**：从 Windows PowerShell 或 Linux 本地连接同一 Linux 服务器，将第三篇项目部署并构建，在 tmux 会话中运行带唯一标识的实验，暂离后重新接入查看状态和日志。

| 章节 | 概念与操作案例 | 掌握结果 |
| --- | --- | --- |
| 1. 连接与主机识别 | SSH、密钥、主机别名、跳板机、心跳；标明每一步在本地还是远端执行 | 能确认服务器、用户和目录，区分心跳与任务保活 |
| 2. 代码与数据同步 | Git 提交同步、版本与修改状态；scp 与 rsync 的用途、目录尾斜杠及预览 | 能说明同步了什么，区分代码、数据与结果；Windows rsync 明确额外环境要求 |
| 3. 环境预检与远端构建 | 主机、工具链、路径、输入、输出空间与版本核对；复用第三篇构建流程 | 编译产物与机器环境匹配，避免把本地二进制直接当作远端可执行程序 |
| 4. 长任务与会话 | 前台/后台、PID、作业控制、tmux、nohup、输出重定向；本地 Windows 进程作为对照 | 能暂离并重新查看任务，知道会话工具不保证系统重启或调度回收后继续运行 |
| 5. 进程状态与停止 | PID、进程树、运行时长、子进程等待、退出记录；正常停止与强制停止 | 能区别运行、退出和成功；记录任务结果，不把 PID 不存在视为成功 |
| 6. 资源与服务检查 | CPU、内存、磁盘/inode、负载、OOM、端口；GPU 显存、利用率与进程，UUID 与可见设备 | 根据证据区分资源不足、进程故障和端口冲突；能识别选卡后的编号变化 |

**关键限制**：Git 同步依赖提交与推送，`.gitignore` 不决定全部同步结果；`disown` 与 nohup 的信号处理不等于完整的任务保活。GPU 空闲检测不提供资源预留，探针失败必须报错或明确停止等待流程；不把空输出直接解释为空闲。

**常见问题**：连接失败、密钥或端口错误、代码未提交、文件未同步、SSH 断开后任务结束、进程被 OOM 杀死、磁盘满、端口占用、GPU 编号误用、任务被调度系统回收。

**命令速查**：连接、同步、会话、进程、CPU/内存/磁盘、端口及 GPU 查询；区分本地客户端依赖和远端工具依赖。

**实践练习**：本地与远端代码版本及输入校验一致；重新接入后能找到指定任务和日志；结束测试任务后记录真实退出状态；能指出“当前空闲”与“获准占用”的区别。

## 第五篇：日志分析与结果整理

**读者与前提**：能查看文本并理解基本管道；不要求编译程序、连接服务器或使用 GPU。

**核心问题**：把多次实验输出整理为结构化数据，避免缺失、重复、误解析和错误比较。

**内容边界**：专注整理与检查，不重新讲解第二篇的运行保活和重定向；不在本篇展开性能实验设计或统计推断。

**主要案例**：提供完整 `fixtures/`，包含正常运行、非零退出、缺失指标、重复键和非法数值日志；两端从同一份素材整理为相同字段的结果表，并按 `case_id` 比较 A/B 记录。

| 章节 | 概念与操作案例 | 掌握结果 |
| --- | --- | --- |
| 1. 日志格式与记录标识 | `run_id`、`case_id`、状态、单位和阶段；原始日志、结构化记录与汇总表的关系 | 能制定字段约定，保留原始证据，不以行号关联不同运行 |
| 2. 检索与上下文 | rg/grep 与 PowerShell `Select-String`；字面匹配、正则、文件名和上下文 | 提取匹配来源，不误把诊断提示或其他阶段指标当作目标结果 |
| 3. 字段提取与数据检查 | 简单 TSV 的 awk/cut；PowerShell 对象属性；键值日志的完整格式检查 | 验证必填字段、数值格式与单位，缺失和重复数据有明确状态 |
| 4. 排序、分组与关联 | 文本排序与对象排序、频次和摘要；按唯一键关联两组结果；缺失匹配与重复键 | 数值按数值排序，关联后保留未匹配记录，不默默丢失样本 |
| 5. JSON 与表格输出 | jq、PowerShell JSON/CSV 工具；结构化数据与显示格式；一般 CSV 的解析限制 | 生成可再次读取的 TSV/JSON/CSV，展示对齐不替代机器可读结果 |
| 6. 结果比较与规模限制 | 文件字节比较、校验和、数值容差；汇总计数与原始条目；大文件内存估算与分块入口 | 区分字节相同、文本等价和数值正确；能核对输入记录数与输出记录数 |

**关键限制**：说明 gawk 扩展与其他 awk 实现的差异，不默认 `awk --version` 在所有实现可用；`grep -P` 取决于实际构建与平台，不能笼统承诺。中位数模板处理空样本、非法值和偶数样本；缺失指标不补零。

**常见问题**：正则过宽、科学计数法未解析、字段顺序改变、把重复日志取最后一次掩盖异常、文本数值排序错误、关联静默丢行、错误编码、对大数组或日志一次性读入导致内存不足。

**命令速查**：按检索、提取、检查、排序、关联、输出和比较分类；高级二进制查看只保留 `file`、十六进制与文件头的最小诊断入口。

**实践练习**：正常、失败、缺失、重复和非法记录均得到约定分类；结果总数与输入运行数对得上；Windows/Linux 的结构化内容一致，不要求 BOM、换行和字节布局完全一致；A/B 未匹配项可见。

## 第六篇：性能实验与诊断工具

**读者与前提**：能构建并验证程序、保存日志、整理结果；CPU 测量可独立完成，CUDA 工具需受支持设备、驱动与权限。

**核心问题**：明确测量范围，控制影响因素，用可追溯的样本比较改动，并使用诊断工具定位瓶颈。

**内容边界**：终端中的实验组织与工具使用为主；CUDA event、具体核函数优化和 Roofline 原理引用 GPU 系列，不重复刊载。CPU 案例是必需主线，GPU 采集是明确标记的扩展实验。

**主要案例**：对同一输入、正确性规则与计时范围运行 A/B 两种实现；分别完成环境记录、预热、A/A 噪声观察、交错运行、失败筛选和汇总。GPU 扩展使用已验证的向量计算程序采集时间线或核函数指标。

| 章节 | 概念与操作案例 | 掌握结果 |
| --- | --- | --- |
| 1. 测量范围与正确性 | 进程总耗时、程序阶段、传输、kernel 与端到端；Linux time 和 PowerShell Measure-Command 的边界 | 比较前先检查正确性；Shell 总耗时不当作 kernel 时间 |
| 2. 环境与资源控制 | 机器、代码与输入、线程数、资源分配、缓存、温度与频率；CPU 亲和性和 NUMA 最小入口 | 记录影响结果的条件；空闲查询不作为独占证明，本地与服务器数据分别解释 |
| 3. 预热与重复实验 | 冷启动/稳定运行目标、预热和正式样本、A/A、交错与平衡顺序、噪声和失败记录 | 预先确定实验规则，不用固定三次或随意丢弃首轮替代证据 |
| 4. 对照运行与结果汇总 | 使用第二篇脚本及第五篇字段；记录顺序与配置，按同一 case 比较样本与摘要 | 原始样本可追溯；给出离散程度，明确加速比方向，不只展示最佳值 |
| 5. 诊断工具与性能证据 | CPU 诊断入口；Compute Sanitizer、nsys 时间线、ncu 核函数指标；限定采集范围与权限 | 根据问题选择工具，区分正确性检查、正常运行计时和带探针采集 |
| 6. 实验记录与结论限制 | 环境快照、参数、输入、提交与修改、工具报告和汇总；有效/无效样本与局限 | 他人能理解如何复跑，结论不超过实际验证范围 |

**关键限制**：程序内确定性操作计数与硬件性能计数器不能统一视为共享环境下稳定；探针、重放和调试选项可改变运行行为。`-lineinfo`、Sanitizer 等选项的影响不作绝对或固定倍数保证；查询失败、权限不足与缺失报告如实保留，不默认使用 sudo 修复。

**常见问题**：计时未同步、比较范围不同、第一轮偏慢、共享资源干扰、GPU 温度/频率变化、冷热缓存不同、诊断开销被算作性能收益、权限不足、错误结果仍进入统计、样本数量不足。

**命令速查**：环境快照、CPU 总耗时与峰值内存、资源查询、GPU 正确性与诊断入口；命令选项随实际工具版本核对。

**实践练习**：A/B 正确性检查均通过；输入、单位和计时范围一致；预热与正式样本分开；运行顺序、原始记录、离散程度及失败原因可查；GPU 报告仅在实际采集完成后引用，无法采集时明确限制。
