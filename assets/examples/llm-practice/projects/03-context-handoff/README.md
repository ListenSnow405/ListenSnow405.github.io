# 实验日志工具比较项目

本项目对应第三篇《上下文组织与项目约束》，用于练习从文件恢复任务。所有工具说明均为教学模拟资料，事实表、比较矩阵和交接说明是按固定资料编写并由写作侧核对的教学快照，不是独立模型运行记录。

## 目标与有效输入

为实验日志整理初学者形成 C1-v1 比较报告，用于选择后续测试候选。

- 当前需求为 D1 版本 1，详见 `sources/index.md` 与 `sources/materials-v1.txt`。
- 使用 S1—S3；不安装工具、不检索最新版本、不开展速度排名。
- 六项必要条件为 R1 平台、R2 输入类型、R3 文件数量及单文件大小、R4 输出列与单位及缺失规则、R5 网络连接、R6 输入保护。
- U1 图形界面为偏好，U2 许可证缺失待确认，不直接淘汰候选。
- 本练习的报告格式约定为 Markdown；模拟工具自身输出 CSV，两者分别表达。

## 文件入口

| 文件 | 职责 |
| --- | --- |
| `rules/AGENTS.md.txt` | 项目约束模板；普通对话中手动提供 |
| `sources/index.md` | 来源标识、版本、位置与有效范围 |
| `sources/materials-v1.txt` | D1 版本 1 与 S1—S3 原文，逻辑行号保持不变 |
| `artifacts/facts-v1.md` | F1-v1，24 行事实教学快照 |
| `artifacts/matrix-v1.md` | M1-v1，18 项必要条件判定及偏好信息教学快照 |
| `state/handoff-v1.md` | H1-v1，当前状态、关键依据、缺口与下一步 |

所有路径相对于这个项目根目录。原资料的 `D1:L3`、`S2:L4` 是文本中的逻辑来源标识，不是整个文件的物理行号。需求存在多个版本时，引用应带需求版本。

F1-v1 和 M1-v1 已作为文件提供，写作侧按固定资料核对；接收方仍须复核版本、完整性及原文依据。C1-v1 尚未生成，不存在 `artifacts/report-v1.md`；其未来路径只是保存建议。

## 恢复流程与验收

1. 普通聊天使用项目外 `prompts/03-01-resume.txt` 的完整粘贴包；它含本项目七份文件，路径只是标识，不要求硬盘访问。文件工具 Agent 则先读取入口、规则、索引和 H1，再读取原资料、F1 与 M1。
2. 只生成恢复清单，核对有效版本、六项条件、产物状态、24 个唯一事实标识与 18 项必要条件判定，回到原文检查，不提前生成报告。
3. 读者实际检查通过后，提交 `prompts/03-02-report.txt`，形成四部分 C1-v1：需求与必要条件、比较矩阵、候选结论与选择依据、待确认信息与执行状态。
4. 停在报告验收点，人工核对后手动保存输出；确认文件存在后再另存新版交接说明。生成文本、保存文件、人工验收、实际工具运行分别记录。

完成标准包括事实完整且唯一、必要条件判断正确、候选均满足六项条件、关键结论有记录标识和原文依据、未知保留、执行范围准确。不能把教学快照状态当作读者已经验收通过。

`expected/03-reference.md` 在项目外，完成练习后再读，不作为模型输入。错误交接与 D1 版本 2 是独立分支，各自替换对应区域；正常恢复不同时加入变体或参考答案。

## 使用范围

本练习中的模型只生成文本，不联网、不安装、不执行文件写入或覆盖。读者可以在独立个人练习目录中手动保存文件。没有实际工具安装、日志处理、速度测试或运行失败记录。

`rules/AGENTS.md.txt` 是普通教学模板。Codex 可选分支由读者在独立练习项目根目录中手动另存为 `AGENTS.md` 并新开会话检查；不要直接在现有工作仓库改名启用，也不要修改全局配置。加载范围与权限依宿主而定，显式读取不等于自动加载验证。
