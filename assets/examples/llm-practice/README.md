在任意文本对话产品中，将输入与文章相应实验的完整要求一起粘贴。三个实验分别独立进行，不依赖 API、上传、网络或文件工具。保留自己的输入、要求、原始输出及检查结论；产品加载的项目规则或记忆如可见，也一并记录。

第一篇的 P0、P1、P2 分别在新对话中提交，保持产品、模型、可见设置和 S1 一致。P0 到 P1 是整体改写，P1 到 P2 只增加示例，不能把一次结果当成稳定性结论。变体练习复制 P1，再用变体替换整个 `<material>` 区域；不追加到原版 S1 后，也不把答案或其他版本同时交给模型。已删除的行不能用作引用，资料未提供的项目移至待确认列表。

第一篇摘要篇幅按非空白字符计数，包含标点、数字和英文字母，排除来源括注、标题和待确认列表，上限 180。导读原有“180 个汉字”要求保持原样，核对各篇时以本篇契约为准。E1/E2 只示范表达与处理规则，不提供 S1 的事实。

参考答案依据固定输入逐项整理。核对字段、行号、缺失处理和状态描述；摘要允许措辞变化。导读与第一篇的操作实验只分析需求，没有执行文件写入；模拟资料不能用作真实产品的能力或最新版证据。导读与第一篇未进行跨模型独立对照评估；第五篇的后续小样本实测单独记录。

后续写作应同步维护文章中的 S1、配套输入和可直接提交的提示词，保留来源编号与字段语义。第一篇 P2 除示例块外须与 P1 一致；更新 P1 时同步 P2。更新输入时另存版本，运行产物保存在独立练习目录或被忽略的临时目录，不放入博客源码。

一号至四号提示词在同一对话按顺序执行，每阶段核对通过后再提交下一号。后续提示词中的“已核对通过”须与实际检查状态一致；未通过时先反馈，不提前作出确认。D1 已回答平台、输入规模与缺失规则，无需重复澄清。

事实记录使用 `LB`、`BT`、`RS` 加 `R1`—`R6`、`U1`、`U2`，共 24 个唯一标识。R 编号映射六项必要条件，U 编号映射界面与许可证；事实表保留原始属性，不提前写适用性结论。矩阵分别检查 18 个必要条件判定，偏好不抵消不满足或资料不足。只有全部必要条件满足的工具才能列为当前资料范围内的候选。

五号提示词是正常流程完成后的替代错误练习：明确切换到人为摘录，资料和需求不变，不把它覆盖为正常流程的原始失败。修订后复查 LogBrief 的事实、R3 判定与候选结论，并保留 BatchTrace 的正确上限与 RunSheet 的未知输入保护。只有摘录时，验收范围限于受影响内容，不能声称整张事实表已通过。

需求变化练习只将 D1:L3 的数量从 6 改为 9，另存 D1 版本 2，工具说明不变。事实值不随需求改写；旧数量判定与候选结论标为待重查，不得自行拆分任务或删除条件以保留旧候选。

参考答案在完成正常流程后读取，不交给被检查模型。写作核对包括输入同步、记录集合、参考判定、模板对应与页面构建；未进行跨模型独立多轮评估、真实工具安装或速度测试。四阶段产物由读者手动保存，不声称模型已经创建文件。
